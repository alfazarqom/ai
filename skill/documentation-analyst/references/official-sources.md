# Official Source Guidance

## Source priority
1. Official product documentation and API reference for the product/version being analyzed.
2. Official changelog, release notes, migration guides, and support articles.
3. Official source repositories or examples when they directly clarify documented behavior.
4. Reputable secondary sources only when official sources do not answer the question; label them as secondary.

## Verification rules
- Confirm the source is relevant to the product, API version, and requested time period.
- Follow cross-links for definitions or constraints that the main page references.
- Distinguish requirements explicitly stated by the source from recommendations or interpretations.
- Cite the exact page supporting each material technical claim.
- If official sources conflict, report the conflict, compare dates/version scope, and avoid silently choosing one.
- If a page cannot be accessed, say so and do not present its contents as verified.
